# Contributing

## Before you change the playbook

- Keep the playbook route working at `/playbooks/steal-your-competitors-audience`.
- Preserve the review-first promise. The guide must not imply that it has researched people or sent outreach when it has not.
- Keep copy direct, specific, and easy to scan. Prefer useful examples over decorative labels.
- Test both the desktop and mobile layout when changing the page or global styles.

## Local checks

Run these before opening a pull request or pushing a change:

```bash
npm run lint
npm run build
```

## Scope changes clearly

Keep a commit focused on one change. Do not mix copy, layout, assets, and configuration changes unless they are required for the same outcome.
